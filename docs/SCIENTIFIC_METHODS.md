# Научные методы

## Система координат и время

Backend запрашивает NASA/JPL Horizons с параметрами `CENTER=500@10`, `EPHEM_TYPE=VECTORS`, `VEC_TABLE=2`, `REF_PLANE=ECLIPTIC`, `OUT_UNITS=KM-S`, `VEC_CORR=NONE`. Результат — гелиоцентрические векторы в эклиптической плоскости J2000; модель сохраняет полный `x,y,z,vx,vy,vz`, Canvas показывает только `x,y`.

Шкала интерфейса принимает UTC. Horizons возвращает эпоху в TDB (`timestamp` — JDTDB, `epochTdb` — исходная календарная эпоха из ответа). Backend преобразует TDB → UTC библиотекой `astropy.time.Time` и сохраняет результат в `epochUtc`; именно `epochUtc` используется для сравнения и интерполяции. TDB и UTC не получают ложных timezone-меток и остаются отдельными полями.

## Производные величины

Для состояния `r=(x,y,z)` и `v=(vx,vy,vz)`:

```text
distance_to_sun = |r|
heliocentric_speed = |v|
distance_to_earth = |r_object - r_earth|
```

Единицы: расстояния km/а.е. (`1 а.е. = 149 597 870.7 km`), скорость km/s. Расстояние до Земли вычисляется только для одновременных гелиоцентрических состояний. Текущая скорость Parker не является его историческим максимумом.

## Интерполяция

При эпохе между двумя контрольными точками приложение использует кубическую Hermite-интерполяцию, то есть одновременно положение и скорость на обоих концах интервала. Производная полинома даёт скорость в выбранной эпохе. За диапазон контрольных точек приложение не экстраполирует: запускается новый ограниченный запрос после debounce.

Точная контрольная точка имеет `interpolation=sampled`; восстановленная — `interpolation=hermite`. UI показывает границы TDB и эвристическую оценку отклонения Hermite от линейного отрезка. Эта оценка не является измеренной погрешностью и не заменяет SPICE/ковариационный анализ.

Для солнечной карты запрашивается шаг 1 день, что повышает плотность ряда для Parker Solar Probe. Для дальнего космоса используется 30 дней. Источник и покрытие (`reconstructed`/`forecast`) отображаются отдельно.

## Ограничения метода

- В MVP не загружаются NAIF/ESA SPICE kernels и не выполняется независимый cross-check каждой точки.
- Вектор относительной скорости к Земле пока не показывается отдельной карточкой; отображается гелиоцентрическая скорость.
- Parser не угадывает coverage по текстовым словам. Начальное значение — `unknown`; adapter классифицирует точку как `forecast` только если её преобразованная UTC-эпоха находится в будущем относительно момента запроса, иначе как `reconstructed`. Если эпоха отсутствует, остаётся `unknown`.
